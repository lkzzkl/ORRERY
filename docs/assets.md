# 素材管线与授权细则

本文件说明**为什么**本仓库能做到零外部素材，以及新增素材时的完整约束。逐项登记见仓库根目录 [ASSETS.md](../ASSETS.md)。

## 1. 管线

```
参数（src/params.js）
  → seed（FNV-1a）
  → 几何数据（src/geometry.js + src/prng.js）
  → SVG 字符串（src/render.js，纯函数、无 DOM）
  ├─→ 预览：main.js 写入 #preview 的 innerHTML
  ├─→ 导出：export.js 安全自检 → Blob 下载（SVG）→ Canvas 栅格化（PNG）
  └─→ 内置海报：scripts/generate-posters.mjs 用同一套纯函数写入 assets/posters/
```

**关键性质**：整条管线不读取仓库外的任何文件、不发起网络请求、不加载字体文件。仓库里能看到的每一张图，都是源码算出来的。

## 2. 素材来源分类对照

按通用的 A1–A8 素材来源分类核对本仓库：

| 分类 | 是否使用 | 说明 |
|---|---|---|
| A1 纯程序绘制 / 几何 / Canvas·CSS 生成 | **使用** | 全部星图、轨道、刻度、页面 UI 形状 |
| A2 像素图 / 位图 | 不使用 | — |
| A3 矢量 SVG / 图标库 | **仅自产 SVG** | 未引入 Lucide / Feather / Font Awesome 等图标库，规避混合授权 |
| A4 字体 | **仅系统族名称** | 不打包 `.ttf/.otf/.woff`，不触发 OFL 的 RFN 与子集化合规问题 |
| A5 音效与音乐 | 不使用 | — |
| A6 文本 / 数据表 | **仅自撰** | 全部文档、界面文案、配色数值均为项目自产 |
| A7 AI 生成图像 / 音频 | 不使用 | 规避权属不确定与无法有效授权的风险 |
| A8 第三方商用 / 引擎商店素材 | 不使用 | 规避 EULA 禁止再分发与公开仓库的冲突 |

## 3. 为什么这套组合对公开仓库最安全

公开仓库 = 向公众再分发（Redistribution）。判断素材能否使用，第一问不是「能否免费下载」，而是「许可是否允许再分发、是否要求署名、是否允许商业使用」。

- A1 + A6 自产内容随代码许可证一次性授权，无署名、无 NC / SA 条款、无再分发限制。
- 无二进制素材 → 无 Git LFS 体积问题，全部产物可 diff、可追溯。
- 无字体文件 → 无 SIL OFL 保留字体名（RFN）与 CJK 子集化修改合规问题。
- 无 AI 生成物 → 无「纯 AI 输出可能不构成受版权保护作品、无法被有效授权」的隐患。
- 无 EULA 素材 → 无「允许用于成品但禁止以可复用形式再分发源文件」的冲突。

## 4. 许可分层（Layered Licensing）

```
LICENSE          → 仅覆盖源代码
ASSETS.md        → 逐项登记素材与产物的权属、许可、修改、使用位置
CREDITS.md       → 面向最终用户的致谢与边界声明
licenses/        → 若将来引入第三方素材，存其许可证全文（当前为空约定）
```

README 明确声明「代码 MIT；素材全部自产；零外部素材」，不写成「全仓库 MIT」——避免读者误认 LICENSE 覆盖了权属不同的内容。项目名与商标单列，不在开源授权范围内。

## 5. 导出产物的自足性

静态 SVG 海报必须离线可开、不含可执行载体。导出前 `src/render.js` 的 `inspectSvg()` 与 CI 的 `scripts/check-assets.mjs` 双重拦截：

| 禁止 | 理由 |
|---|---|
| `<script>`、内联事件、`javascript:` | 静态文件不应成为可执行载体 |
| `<image>`、`<foreignObject>`、`href` / `src` | 外部资源引用会让海报离线失效 |
| `@font-face`、`@import`、CSS `url()` | 远程字体加载与嵌入 |
| 任何 `https?://` 绝对 URL | 除 `xmlns` 命名空间标识外无例外 |
| 未转义文本 | 所有动态文本经 `escapeXml()` |

`xmlns="http://www.w3.org/2000/svg"` 是唯一白名单：它是规范固定标识，不发起请求。检查前归一化为占位符，避免合法 SVG 被误报；同时单测含真实注入样本，验证不会漏报。

## 6. 新增素材流程

1. 先确认是否真的需要外部素材——本作的机制允许用 A1 程序化生成替代绝大多数需求。
2. 若确需引入，在 `ASSETS.md` 补齐七个字段：素材名、作者、来源 URL、许可、修改说明、使用位置、获取日期。
3. 把许可证全文放入 `licenses/<素材名>.LICENSE`，并在登记行链接。
4. 第三方素材按来源放在 `assets/third-party/<vendor>/`，目录内自带 `SOURCE` 与 `LICENSE` 副本，避免文件被单独复制后丢失权属信息。
5. 字体单列分区；如需打包，必须 SIL OFL 并附 `OFL.txt`、核对 RFN、确认允许子集化。
6. 运行 `npm run check-assets`，PR 附输出。

### 一律禁止

CC-BY-NC（非商用，与公开仓库的潜在商业使用冲突）、CC-BY-SA（相同方式共享的传染性，会与 MIT 相斥）、专有 EULA 素材（普遍禁止再分发源文件）、含商标或真实角色外观的位图、外包文案（需先书面著作权转让）、从 Wiki 抓取的 SA 文本。
