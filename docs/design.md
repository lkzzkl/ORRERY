# 设计说明（GDD / 概念与规格）

> 项目：ORRERY / 星图 ｜ 版本 1.0.0 ｜ 阶段：已实现的最小可玩版本（Minimum Viable Product, MVP）

## 1. 一句话定位

一款无胜负的星系编排玩具：调参、观察、定格，把成果导出成一张矢量海报。

## 2. 设计支柱（design pillar）

| # | 支柱 | 具体约束 | 违反即返工 |
|---|---|---|---|
| P1 | **参数少，结果多** | 可见参数控件 ≤5；结果空间由确定性几何而非控件堆叠产生 | 增加第 6 个控件、以堆参数换变化 |
| P2 | **产物即作品** | 每次游玩都留下一张可带走、可提交进仓库、可放 README 首屏的静态 SVG | 产物只能停留在页面内、需另做宣传物料 |

## 3. MDA 拆解

| 层 | 内容 |
|---|---|
| Mechanics（机制） | 参数到几何的确定性映射；5 个有界控件；定格与导出动作 |
| Dynamics（动态） | 玩家把「玩」转化为「构图」：反复微调直到满意，或自设目标（三星共线、只用两色） |
| Aesthetics（美学） | Sensation（静谧）、Expression（自我表达）、Submission（可反复把玩） |

## 4. 核心循环（core loop）

```
打开页面 → 拖动参数 → 实时看到星图重排（可选缓慢公转）
        → 定格 → 导出 SVG / PNG 海报 → 换一组参数重来
```

- 无回合、无实时对抗、无关卡序列、无强制推进。
- 装饰性公转 **不改变几何数据**，只是预览层的 CSS 动画；导出的海报是静态且确定的。这是 P2 能被「可复现」验证的前提。
- 玩家自设目标构成可重玩性；不提供系统评分。

## 5. 单局流程与胜负规则

| 项 | 规则 |
|---|---|
| 单局 | **无单局概念**，单次会话 2–10 分钟，可随时离开 |
| 推进 | 无强制推进，靠自设目标与导出次数 |
| 结束条件 | **无**，不设胜负、评分、通关、失败 |
| 跨会话保留 | 本地参数预设 JSON 文件、导出的海报文件；不写云端、不写账号 |
| 可重玩性 | 参数空间 7 × 66 × 17 × 91 × 3 = 2,144,142（≈ 2.14M）组合，叠加自设挑战与配色收集 |

> 复杂度口径：本作**没有游戏状态机**，只有参数到几何的一次性映射。因此不存在存档迁移、状态机边界、经济平衡等常见风险。

## 6. 参数规格

| 参数 | min | max | step | default | 单位 | 语义 |
|---|---|---|---|---|---|---|
| `orbits` | 3 | 9 | 1 | 5 | 条 | 轨道层数；半径按 `0.26 + 0.74 × (i+1)/n` 分布 |
| `eccentricity` | 0 | 0.65 | 0.01 | 0.28 | — | 短半轴 `ry = rx × (1 − 0.72e)` |
| `density` | 0.2 | 1.0 | 0.05 | 0.6 | — | 第 i 层星体数 `round(2 + d × (3+i))` |
| `tilt` | −45 | 45 | 1 | 12 | 度 | 逐层偏转 `tilt × (i − (n−1)/2)/(n−1)` |
| `palette` | 0 | 2 | 1 | 0 | — | 深蓝夜航 / 纸本星图 / 无色高对比 |

所有范围、步长、默认值集中在 `src/params.js` 的 `PARAM_SPEC`。外部输入（URL、JSON 预设）一律经 `clampParams()` 夹取，`null` / 空串 / 非数值视为缺失回落默认值，不静默转成 0。

### 确定性

`seed = FNV-1a(canonical(params))`，再由 `mulberry32(seed)` 生成星体角度、大小、色调与环标记。同一组参数必然得到同一个 `system` 对象和逐字节相同的 SVG；`tests/geometry.test.js` 与 CI 的海报 diff 双重保证这一点。

## 7. MVP 范围分层（MoSCoW）

### Must（1.0.0 已完成）

- 4–5 个参数控件、确定性轨道几何生成、实时 SVG 重绘
- 定格、SVG 导出、2–3 套配色预设
- 仓库文档、许可分层标注、示例海报、单测与 CI

### Should（1.0.0 已完成）

- 参数预设导入/导出、PNG 导出、随机生成按钮、可关闭的公转动画

### Could（部分完成）

- 已完成：URL 参数分享链接
- 未做：打印/海报尺寸预设、程序合成环境音、挑战卡（如「三星共线」判定）

### 本版不做什么

- 任何胜负、评分、关卡、进度、成就
- 账号、云存储、多人协作、服务端
- 物理真实性模拟、3D
- 外部图片、字体文件、音频、AI 生成素材
- 前置构建步骤与运行时框架

## 8. 可访问性规格（目标：Standard / WCAG 2.2 AA）

| 维度 | 落地方式 |
|---|---|
| 对比度 | 页面正文 ≥ 4.5:1；三套配色的正文与次要文字实测 5.4:1–19.8:1、轨道线与星体色 4.97:1–19.8:1，由 `tests/geometry.test.js` 逐色断言守住 |
| 色盲友好（CVD） | **不把颜色当唯一编码**：星体以三档明度色 + 尺寸差异 + 环标记共同区分，另提供「无色高对比」配色；轨道层数、星体数、参数与 seed 同时以文字印在海报上并写入 `<desc>`，读不出颜色也能取到全部信息。**注意**：色调（`tone`）与尺寸、环标记是两个独立的确定性随机量，并非一一对应的形状映射，故此处不宣称「形状编码颜色」 |
| 字号与缩放 | 相对单位、200% 缩放不裁切、行高 ≥1.5 |
| 键盘 / 触屏 | 全流程原生可键盘操作、可见焦点指示、逻辑 Tab 顺序、按钮命中区 ≥44×44 CSS px |
| 动效与闪烁 | 无 3 Hz 以上闪烁；装饰性公转可关闭；`prefers-reduced-motion` 自动关闭 |
| 字幕 / 文本替代 | 无音频；预览 SVG 内含 `<title>` 与 `<desc>`（含轨道数、星体数、配色与参数），可供辅助技术读取 |

> Canvas 方案常见缺陷（屏幕阅读器读不到画布）在本作不存在：预览与产物都用内联 SVG，天然是 DOM 可读的矢量文本。

## 9. 已知取舍

| 优点 | 取舍 |
|---|---|
| 呈现成本最低，README 首屏即作品 | 无胜负与进度，「是否算游戏」需靠本文件定义玩法边界 |
| 零依赖、零素材、零授权风险，离线可开 | 深度有限，易被视作可视化小工具 |
| 参数少、30 秒上手，受众面最广 | 观感高度依赖配色与排印，设计不达标时落差明显 |
| 纯函数核心，确定性与安全性可自动化验证 | 无引擎能力，无法扩展为 3D / 联网类玩法 |

## 10. 后续扩展方向（未排期）

1. **轻量化挑战卡**：加入「三星共线」「只用两色」等自设目标判定，做成无惩罚解谜，仍不引入胜负。
2. **可分享的每日星图**：把参数编码进 URL 与打印尺寸预设，扩展为可分享的静态海报系列。
